11:T2ffe,<h1 id="problem-cmos-ota-output-stage-layout-task">CMOS OTA Output Stage Layout Task</h1>
<h2 id="problem-objective">Objective</h2>
<p>Create an IHP SG13G2 layout for the <code>output_stage</code> output stage of a two-stage
CMOS operational transconductance amplifier. Preserve the device topology,
dimensions, compensation capacitor, explicit well and substrate connections,
and five-port interface in the authoritative materials. The submitted GDS must
pass the physical checks, fit the functional outline, and meet the nominal
output-response limits after candidate-derived RC extraction.</p>

materials. The structured constraints

<h2 id="problem-physical-requirements">Physical Requirements</h2>
<p>Submit a readable GDSII file with a nonempty <code>output_stage</code> top cell. The file
must be at most 10 MiB (10,485,760 bytes) and must contain the complete
hierarchy needed by the target cell.</p>
<p>The evaluator runs the pinned SG13G2 main and additional maximal DRC rules in
deep mode, with density and antenna checks disabled and no waivers. LVS uses the
current <code>lvs-upstream.json</code> profile and strict named-port matching against
<code>materials/circuit.cdl</code>; every declared port must stay on its own conductor
with the declared connectivity and device parameters. Port names are matched
case-insensitively.</p>
<p>The functional outline is the recursive bounding box of polygons on these
SG13G2 datatype-0 layers, including child cells and the complete routing stack:</p>
<p><code>1, 3, 5, 6, 7, 8, 10, 11, 13, 14, 19, 24, 26, 28, 29, 30, 31, 32, 33, 35, 36, 40, 44, 46, 49, 50, 51, 52, 53, 55, 58, 66, 67, 90, 101, 111, 125, 126, 128, 129, 133, 134, 139, 152</code>.</p>
<p>The maximum width is 55 µm and the maximum height is
45 µm, measured along the submitted X and Y axes.
Functional area is width multiplied by height. Text, annotation and filler
layers are excluded. The area score below uses this same functional footprint.</p>
<p>After the physical and geometry gates pass, Magic extracts distributed wire
resistance and layout capacitance from the submitted GDS. Device merging and
resistor-network simplification are disabled. The compact-device extraction
boundary represents MOS bodies at ideal model rails; explicit taps remain in the
physical LVS netlist but are not emitted as extracted tap elements. Substrate
sheet and tap resistance as extracted quantities, body coupling, and noise are
outside the declared scope. The finite source taps are used only in source calibration.</p>
<h2 id="problem-electrical-requirements-and-scoring">Electrical Requirements and Scoring</h2>
<p>Physical checks and declared functional bounds remain mandatory. Quality has no
fixed allowed-degradation threshold. Each <code>source_*</code> job simulates the declared
source circuit with exactly the same testbench, model resources, parameters,
load and measurement window as its paired extracted-candidate job. A source
observation is the 100-point electrical baseline; it is independent of the
submitted GDS. All individual pairs are retained in the evaluation report.</p>
<p>For a post-layout observation x and its source observation b:</p>
<ul>
<li>Maximize: q = x/b; minimize: q = b/x. When a numerical scale s is declared,
use (x+s)/(b+s) or its inverse. This handles zero-valued error measurements;
s is a normalization floor, not an allowed degradation or pass threshold.</li>
<li>Amplitude dB: q = 10^((x-b)/20) for maximize, its inverse for minimize.</li>
<li>Target: q = 1/(1+abs(x-b)/s), with a declared physical scale s. Signed and
zero-valued operating points are never divided directly.</li>
</ul>
<p>Scoring uses <code>layout</code>. A metric uses its worst paired quality q. The score is
S = 100 * product(q_i ** w_i), including area quality
q_area = area_reference / candidate_functional_area. The weights below sum to
one. Dimensions describe measurements but do not determine their weights.
Physical or functional rejection scores zero; missing or invalid measurements
produce an unknown score, including measurements with zero weight.
Source-equivalent performance at the area reference scores 100; improvements
can exceed 100. A weight expresses a tradeoff, not a hard acceptance limit.</p>
<p>Measurement definitions below use the supplied SPICE node/source names.
<code>v(n)</code> is node voltage and <code>i(V)</code> is current into a voltage source; delivered
power therefore uses a minus sign. <code>db(z)=20*log10(abs(z))</code>, <code>mag/abs</code>
denote magnitude, and <code>cph</code> is continuous phase in radians. <code>find</code>, <code>when</code>,
<code>from/to</code>, and <code>rise/fall</code> retain the deck's interpolation, window and
crossing conventions; SPICE suffixes p/n/u/m/meg/g mean pico/nano/micro/
milli/mega/giga. Nested <code>avg</code>, <code>min</code>, <code>max</code>, <code>vecmin/vecmax</code> and <code>deriv</code>
mean the stated window average, extrema and sampled derivative. All
declared conditions are measured separately and paired with the same
source condition; a group uses its worst paired quality.</p>

<h2 id="problem-tools-and-submission">Tools and Submission</h2>
<p>Solve budget: <strong>3 hours</strong>.</p>
<p>Runtime environment and support resources are declared in
<code>/protocol/resources.json</code> and <code>/protocol/harness.json</code>; the working directory is
<code>/workspace</code>. KLayout performs artifact, DRC, LVS, and geometry checks; Magic
performs RC extraction; ngspice runs the supplied deck with the reviewed SG13G2
models. The evaluator provides the tool and PDK resources named by the case
toolchain.</p>
<p>For pre-layout simulation, use <code>materials/circuit.spice</code> as <code>dut.spice</code> beside
the supplied testbench. The evaluator generates <code>parameters.spice</code> from the
per-job values in <code>/protocol/task.json</code> and supplies the model paths and settings
through the runtime resource bundle. For the submitted layout, the evaluator
supplies the candidate-derived extracted netlist. If the harness declares
<code>process-feedback</code>, the optional command is
<code>python -I /protocol/process_check.py</code>; the final evaluation remains independent.</p>
<p>Write the result to <code>/workspace/output/final.gds</code>, then run
<code>python -I /protocol/submit.py</code> and wait for the submission receipt. Solver
netlists, waveforms, and measurements are not accepted as substitutes for the
independent evaluator inputs.</p>
