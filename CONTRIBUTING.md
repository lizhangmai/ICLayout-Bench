# Contributing and Verification

Public owns participant code, shared definitions, preparation, isolated sessions,
EDA backends, independent evaluation and the local HTTP adapter. Private owns
operator admission, controlled reruns and reviewed releases. Public installation
and CI must not import `layout_operator`. Exclude `third_party/` from framework
searches, lint and tests.

<a id="verification"></a>

## Verification

From Public, offline checks need neither Docker nor Private:

```bash
uv sync --locked --group analysis
uv run --locked ruff check .
uv run --locked python scripts/check_docs.py
uv run --locked --group analysis pytest -m unit
uv build --out-dir build/dist
git diff --check
```

Check built distributions from outside the checkout or with Python `-I`, and
assert that imports come from the installation environment. A source-tree import
cannot validate a wheel. The wheel includes all three Public packages and their
runtime data; it excludes operator modules. Follow [test conventions](tests/AGENTS.md)
before adding regressions.

Reuse a compatible image for container and shared evaluator changes:

```bash
ICLAYOUT_BENCH_TEST_IMAGE=iclayout-bench-tools:dev uv run --locked pytest -m acceptance_container
uv run --locked python -m layout_eval.preview prepare \
  --case cell_6t --image iclayout-bench-tools:dev --output build/prepared-cell6t-http
ICLAYOUT_BENCH_PREPARED=build/prepared-cell6t-http ICLAYOUT_BENCH_TEST_IMAGE=iclayout-bench-tools:dev \
  uv run --locked pytest tests/test_http.py
ICLAYOUT_BENCH_TEST_IMAGE=iclayout-bench-tools:dev uv run --locked --group eda pytest \
  tests/integration/test_public_references.py -k 'cell_6t or NAND2_X1'
```

The prepared directory is generated by the preceding command; use a new directory
for each check. Reference/counterexample tests prepare their own resources. A judge,
scoring, backend or task change requires all affected case checks and shared
regressions under the [qualification rules](docs/tasks.md#qualification), not just
the two-case smoke selection above. Synthetic protocol tests do not establish
model ability or physical validity. Run operator admission/rerun/disclosure checks
in Private when shared changes affect its consumers.

Tool changes follow [image development](docs/tools.md#image-development). Dockerfile,
pyproject and lockfile own versions. Report image reuse/derivation/rebuild and actual
checks. `build/` holds disposable generated data.

## Ownership and review

Update the owning guide when interfaces change. Architecture owns the shared
protocol and module responsibilities; running owns local/remote participation;
tools owns preparation/backend setup. Private documents formal operator workflows.
Markdown is English except README_CN.md. Preserve unrelated changes and verify and
commit affected repositories separately.

<a id="ci-cd"></a>

## CI and release

Public push/PR checks cover lint, documentation, offline regressions and independent
wheel installation. Its manually dispatched EDA workflow builds the public image
and checks containers, HTTP sessions and selected public references without Private.
Private's own workflow pins a compatible Public revision and verifies operator
behavior against it. Release builds publish Public packages and the tools image;
hidden assets, credentials and raw model transcripts never enter those artifacts.
